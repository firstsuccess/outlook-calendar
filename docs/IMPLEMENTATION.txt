構成
React + TypeScript + Vite静的ビルド。Node.js常駐不要。バックエンド・DB不要。
src/auth.ts: Entra単一テナントのMSAL SPA認証（Authorization Code + PKCE）。
src/graph.ts: Graph URL境界、読取専用ガード、401再試行、429/503 Retry-After、ページング。
src/excel.ts: SharePoint / OneDrive for BusinessのURLまたは管理者のdriveId/itemIdから取得。
read-excel-fileでOrganizations/Membersシートをメモリ解析。先頭行の列名を検証。書込APIなし。
src/model.ts: 元の組織ツリー・IsActive・順序・循環検証。無効組織の子も非表示。
src/preferences.ts: テナント・利用者別ブラウザ設定。allとcustomの選択モード。
src/calendar.ts: 最大20名ごとにgetSchedule。UI期間は1日または1週（62日未満）。
本人の/me/calendarsに列挙される共有予定表だけcalendarViewを照会し詳細を照合。
メール→UPNの推定、ディレクトリ全件検索、アプリケーション権限は使用しない。
src/CalendarGrid.tsx: 正確な開始終了から配置、重複レーン、日週・縦横・固定ヘッダー。
src/guide.tsx: 日英中の利用・導入・プライバシー・サポート・試験ガイド。
scripts/release.mjs: 環境別ManifestとPNGアイコン生成。再ビルドでdistへ配置。
scripts/Deploy.ps1: 新規フォルダへの手動コピー専用。IISやサービスは設定しない。

権限と安全性
User.Read: サインイン利用者の識別。
Calendars.ReadBasic: getSchedule（委任）。
Calendars.Read.Shared: 本人がアクセス可能な共有予定表詳細（委任）。
Files.Read.All: 本人がアクセス可能な既存共有ライブラリの組織Excel（委任）。
Sites.Read.All: URLからサイト・ライブラリを解決する場合のみ（管理者同意対象）。
driveId/itemIdを共通設定に明示するとSites.Read.Allは要求しない。
各テナントの同意ポリシーにより他の権限も管理者同意が必要な場合がある。
Excel用の書込権限、User.ReadBasic.All、アプリケーション権限は追加しない。
getScheduleは照会目的のPOSTのみ。Graphクライアントは他のPOSTを禁止。
私的・機密の詳細は常に保守的に消去し、自由記述をHTMLとして描画しない。
本文は共有アクセス成功時のbodyPreviewだけを表示。添付ファイル・HTML本文は取得しない。
同一時刻の予定の照合に限定し、共有カスタム予定表を本人の主予定表の空き判定へ流用しない。
取得失敗・権限拒否・unknownは共通空き判定を停止。
アクセストークン・予定・組織データ・ダウンロードURLを永続保存しない。
Graph失敗ログは画面上の一般コードのみ。件名・本文・トークンはログに残さない。
CSPをHTMLへ設定。配備ホストで同等のCSPとHSTS、X-Content-Type-OptionsをHTTPヘッダーにも設定する。
SharePointダウンロード先はMicrosoftのHTTPSホストに限定、Bearerを転送しない。
公開config.jsonは秘密情報を含めない。共通設定更新APIは設けず配備管理者のみ編集。
Excel参照先は全利用者が登録・変更・解除可能。テナント・アカウント別にローカル保存。

ENTRA_SETUP
1. Entra管理センター→アプリ登録→この組織ディレクトリのみ。
2. SPAプラットフォームを追加。HTTPSのサイトルート（末尾/）をリダイレクトURIへ。
3. 上記Graph委任権限を追加。必要な管理者同意を付与。Client Secretは作成しない。
4. public/config.jsonへclientId / tenantIdのみ入力。Excel URLはサインイン後に各利用者が設定画面で登録。
   共有URLが不透明なリンクなら設定画面の詳細設定でDrive ID / Item IDを利用者が登録。
5. .env.exampleを参考に公開URLを指定して再ビルド。EntraのURIと配備先を一致させる。
6. Excelと予定表の共有権限はMicrosoft 365側で通常の方法で管理する。
7. 権限取消後は画面の更新を実施。古い予定を破棄したうえで再照会する。

既知の設計上の制約・未検証
任意のGraph将来期間APIではなく日週照会に限定。可用性表示文字列への丸め描画はしない。
全日の予定はgetScheduleが返す区間をそのまま描画し、calendarView照合時に終日を明示。
未追加の共有予定表は詳細対象外。メール別名とowner.address不一致では詳細へ昇格しない。
private/confidentialは実際の代理権限にかかわらず詳細非表示の保守的仕様。
詳細照合は同一開始終了に限定。主予定表とカスタム予定表の同一時刻の詳細混在は要試験。
非常に大きい組織の仮想スクロールは未実装。10MB / 5万行のExcel上限。
Teams登録は初期版対象外。Webアプリ分離により将来の個人タブへの展開が可能。
Graphの伝搬遅延・MSALのトークン有効期間中の取消反映遅延は実環境で確認する。
複数テナント版は、許可リスト・テナント別設定・同意導線を別途実装する。
